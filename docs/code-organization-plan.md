# План организации кода перед релизом

Вернуться к этому плану ближе к релизу. Сейчас это не задача на рефакторинг и не основание менять поведение системы.

## Цель

Упростить развитие листов Коммерсанта и Кооператива, сохранив правила, интерфейс, локализацию, права, существующие документы и совместимость с Foundry VTT 14.

## Предлагаемая последовательность

1. **Разделить шаблон листа.** Вынести вкладки из `templates/actor-notes.hbs` в отдельные шаблоны, а повторяемые строки записей, заголовки и элементы журнала — в общие частичные шаблоны. Сохранить расположение элементов, фокус, прокрутку и состояние вкладок, поиска и сортировки.
2. **Разделить подготовку представлений.** Вынести из `Ouw25ActorSheet._prepareContext` подготовку данных Коммерсанта, судна, записей и связанных заметок в небольшие модули. Использовать текущие независимые функции правил; не дублировать данные актёра как второй источник истины.
3. **Уточнить границы действий.** Группировать обработчики по операциям рейса, проверкам, записям и журналам. Очереди автосохранения, повторная проверка прав, защита от параллельных операций и порядок обновлений остаются частью контракта листа.
4. **Унифицировать карточки чата.** Выделить общие части заголовков, строк и раскрываемых подробностей для проверок и рейса без изменения получателей, режимов броска и данных Foundry Roll.
5. **Разбить стили по компонентам.** Отделить общие переменные, листы, формы, записи, карточки чата и диалоги. Сохранить порядок подключения, область действия селекторов и текущую художественную концепцию.

## Условия выполнения

- Делать изменения небольшими независимыми шагами, не совмещая их с изменениями игровых правил или данных документов.
- Сохранять права `Owner` и `Observer`, приватность заметок и сообщений, атомарность перехода сектора и поведение отмены.
- Сохранять создание журналов и страниц только по соответствующей кнопке; не менять автоматически существующие ссылки и права.
- Перед каждым шагом определить затронутые сценарии и использовать существующие тесты вместе с необходимыми проверками поведения интерфейса.
- Не привязывать реализацию к сторонним модулям. Разрешение спорных правил драматического торга остаётся отдельной задачей.
