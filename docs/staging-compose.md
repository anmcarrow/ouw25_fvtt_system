# Staging Foundry VTT в Podman

`compose.yaml` запускает отдельный Foundry VTT 14.370 на
`http://127.0.0.1:31000`. Это staging, а не dev: установите в нём систему из
манифеста конкретного GitHub-релиза и создайте отдельный мир для проверки.
Система и мир нативного dev-инстанса не подключаются к контейнеру.

Данные, настройки, миры, установленные пакеты и кеш дистрибутива хранятся в
именованном томе Podman внутри Linux VM (`ouw25-staging_foundry-data`). Прямые
bind-mount каталогов macOS не используются: это позволяет не зависеть от
настроек общего доступа к путям Podman Desktop и не размещать базу мира на
общей файловой системе. Не удаляйте том при обычном обновлении контейнера.

## Первый запуск

1. Запустите Podman machine через Podman Desktop. Потребуются Podman и
   совместимый Compose provider.
2. На странице [лицензий Foundry](https://foundryvtt.com/me/licenses) выберите
   дистрибутив **Node.js** версии 14.370 и получите временную ссылку загрузки.
   Она действительна ограниченное время и является секретом.
3. Из корня `ouw25_fvtt_system` введите ссылку без отображения в терминале и
   запустите контейнер:

   ```sh
   read -rs FOUNDRY_RELEASE_URL
   export FOUNDRY_RELEASE_URL
   podman compose up -d
   unset FOUNDRY_RELEASE_URL
   ```

   Ссылка передаётся контейнеру через переменную окружения и может быть видна
   пользователям с доступом к Podman; не публикуйте вывод `compose config` или
   `podman inspect` с этой переменной. Не сохраняйте ссылку в репозитории.
4. Откройте `http://127.0.0.1:31000`, введите лицензию и завершите настройку
   Foundry. Лицензионный ключ не входит в конфигурацию проекта.
5. Установите нужный релиз системы и создайте staging-мир.

Образ кеширует дистрибутив в томе `/data/container_cache`. Для последующих
запусков без временной ссылки кешированный архив должен оставаться доступен;
после удаления кеша или смены версии потребуется новая ссылка. Параметр
`CONTAINER_PRESERVE_CONFIG` сохраняет настройки, изменённые через интерфейс
Foundry, при последующих запусках.

## Управление и сохранность

Из корня проекта:

```sh
podman compose ps
podman compose logs --tail=100 foundry
podman compose stop
podman compose up -d
```

Перед обновлением Foundry, системы или мира и перед удалением контейнера
создавайте резервную копию staging-данных; для согласованной копии остановите
Foundry. `podman compose down -v` удаляет том вместе с мирами и кешем и не
является обычной командой остановки.

Образ закреплён за версией 14.370, чтобы staging соответствовал текущему
нативному Foundry. Обновляйте версию осознанно и после резервного копирования.
Привязка порта только к `127.0.0.1` предназначена для локального доступа.
Соблюдайте [условия лицензии Foundry](https://foundryvtt.com/article/license/):
при одной лицензии только один экземпляр может быть доступен другим
пользователям.
